AI UI Testing Agent

Describe a workflow in plain English, review proposed steps, then save a runnable test.

AI proposes. You approve. The runner executes.

AI generation (non-deterministic): The same instructions can produce different steps. Check that every instruction is covered.

Test execution (deterministic): Approved steps run as written, without AI. Results depend on the website and test data; a pass only proves the executed checks passed.

Using the AI UI Testing Agent

First-time setup: GroqCloud API key

Required for AI generation. In the project root (the folder containing package.json), copy the tracked template .env.example to a new local file named .env:

cp .env.example .env

Open .env and replace the empty GROQ_API_KEY value with your personal API key:

GROQ_API_KEY="gsk_your-actual-key"
GROQ_MODEL=openai/gpt-oss-20b

Create or manage your GroqCloud API key

Save .env and restart the local application server. Never share or commit your key or .env file. Git ignores .env, so future pulls can update .env.example without overwriting your local settings. The app reads your key on the server; do not paste it into test instructions.

Optional: GROQ_MODEL=openai/gpt-oss-20b selects the model (already the default). The required variable is GROQ_API_KEY, not GROK_API_KEY (Grok/xAI is a different service).

Using the prewritten demonstration and executing already approved tests does not require an API key.

This is a prototype for creating and running browser tests from plain-English instructions. You review and approve every generated step before it becomes an executable test.

AI generation versus test execution

AI generation (non-deterministic) may produce different steps from the same instructions. Approved tests execute as written (deterministic), without AI; outcomes can vary with the website and data. A pass only proves the executed checks passed.

Quick start

  1. Enter a test name, the application URL, and the actions and checks you want performed.
  2. Choose GroqCloud to generate a draft with AI, or the prewritten demonstration to explore the review workflow without an AI call.
  3. Inspect the proposed actions, targets, and assertions. Edit incorrect steps and confirm each step before saving.
  4. Save the approved JSON test; select it under Run Tests to execute with Playwright and review results and failure evidence.

Editing and incremental regeneration

You can edit individual steps manually. Reinterpret with AI is temporarily unavailable while execution fidelity is being improved. Use Edit fields to correct steps manually. A working draft can be saved before all steps are approved.

Important limitations

  • AI is non-deterministic. The same instructions may produce different actions or occasionally invalid output. Review steps and execution results rather than assuming they are correct.
  • Selectors and expectations can be wrong. A successful AI response does not prove the test represents your intent; complex or dynamic sites may need manual edits or selector repair.
  • Incremental regeneration sees the initial page snapshot, not the live page after preceding steps. Later-page controls may be missing from its context.
  • Working instructions are an amendment history. Previous wording may remain even after steps are replaced. The reviewed steps determine what is executed.
  • GroqCloud requires a configured API key and has rate/token limits. AI requests can fail, but manual review and execution of saved tests do not require a Groq call.
  • Memory is experimental. Do not assume every previous interaction, site, or deployment has reusable verified memory.

This prototype is intended for local development and evaluation. Only run tests against applications you are authorized to test.
