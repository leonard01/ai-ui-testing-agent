# Adaptive regression execution and AI diagnostic design

## Evidence (27 November 2026)
The local full regression run with automatic parallelism reported 212/216 passing in 357.79 seconds. The single-worker run passed 216/216 in 364.21 seconds, with no skips or retries. Review test cumulative time fell from 261.49 to 125.70 seconds. This supports resource contention as a hypothesis, not a proven root cause; hardware usage was not captured during those runs.

## Execution profiles
`npm test` selects a local profile using OS-reported available CPU parallelism, total RAM and free RAM at startup. Low-spec: fewer than four available CPUs, below 8 GiB total, or below 4 GiB free. Performance: at least eight CPUs, 16 GiB total and 8 GiB free. Otherwise standard. These are provisional heuristics, not validated requirements. OS memory may not reflect container limits or reclaimable memory. CI defaults to a fixed two workers; validate on actual runners. Explicit overrides: `npm run test:low-spec`, `npm run test:parallel`, `npm run test:performance`; `TEST_PROFILE` can also be set. All preserve coverage and verdicts. The runner writes `test-results/environment.json` beside JUnit, including effective selection, initial resource snapshot, elapsed time and exit status. Run profiles sequentially to avoid overwriting reports. Direct Playwright commands remain available for custom experiments. No AI calls in the deterministic runner.

## Proposed AI diagnostics (not implemented)
Separate regression-run diagnostics (framework under test) from end-user script execution diagnostics (application under test). Start with explicit opt-in analysis of a single failed regression run, then support comparison across runs and application execution reports. Deterministically aggregate failure signatures, timings, environment metadata and known error categories. Send a bounded, redacted evidence package, not raw traces, screenshots, DOM, credentials, source paths or full logs by default. Treat evidence as untrusted data. Reuse the provider adapter and token budget telemetry; use structured output, validate schema and evidence references, distinguish observations from hypotheses, list alternative explanations and suggested reproduction experiments. No automated code edits, retries, verdict changes or mandatory provider calls. Keep diagnostics available offline if AI is unavailable. Track token cost, diagnosis usefulness, false attribution and sensitive data leakage with mocked and separate live evaluations. A resource contention hypothesis must never convert failures into passes.

## Acceptance
Unit test resolver boundaries and precedence. Verify local automatic selection, explicit override, report creation and nonzero exit propagation. Run full low-spec regression; compare standard and performance profiles later. Confirm actual CI workflow passes with fixed concurrency and retains reports. AI diagnostics is a separate feature with its own acceptance criteria.
