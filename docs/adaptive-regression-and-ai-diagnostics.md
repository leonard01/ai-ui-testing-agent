# Adaptive regression execution and AI diagnostic design

## Evidence (27 November 2026)
The local full regression run with automatic parallelism reported 212/216 passing in 357.79 seconds. The single-worker run passed 216/216 in 364.21 seconds, with no skips or retries. Review test cumulative time fell from 261.49 to 125.70 seconds. This supports resource contention as a hypothesis, not a proven root cause; hardware usage was not captured during those runs.

## Execution profiles
`npm test` selects a local profile using OS-reported available CPU parallelism, total RAM and free RAM at startup. Low-spec: fewer than four available CPUs, below 8 GiB total, or below 4 GiB free. Performance: at least eight CPUs, 16 GiB total and 8 GiB free. Otherwise standard. These are provisional heuristics, not validated requirements. OS memory may not reflect container limits or reclaimable memory. CI defaults to a fixed two workers; validate on actual runners. Explicit overrides: `npm run test:low-spec`, `npm run test:parallel`, `npm run test:performance`; `TEST_PROFILE` can also be set. All preserve coverage and verdicts. Each wrapper run creates a unique timestamp/profile/UUID directory under `regression-history/`, outside Playwright's cleanup directory. It records schema version, run ID, Git commit (if available), tracked dirty state, platform, architecture, Node version, test arguments, profile, resource snapshot, end free memory, duration and exit status. JUnit, HTML and available Playwright evidence are generated directly in that directory; latest convenience copies are published to `test-results/` and `playwright-report/`. No stale JUnit is copied if a run produces no report. Run wrappers sequentially when using latest copies and the shared demo server. Direct Playwright commands bypass archival. Historical files may include sensitive test evidence; keep local, do not commit or send wholesale to AI. No automated deletion is configured; prune deliberately when needed. No AI calls in the deterministic runner.

The standard two-worker smoke run passed 10/12 in 39.71 seconds; both failures were five-second fixture-generation waits. The one-worker full suite passed 216/216. Do not alter automatic hardware thresholds until the corresponding environment report is inspected; use the explicit low-spec profile on the affected machine.

## Proposed AI diagnostics (not implemented; future release)
Separate regression-run diagnostics (framework under test) from end-user script execution diagnostics (application under test). Start with explicit opt-in analysis of a single failed regression run, then support comparison across runs and application execution reports. Deterministically aggregate failure signatures, timings, environment metadata and known error categories. Send a bounded, redacted evidence package, not raw traces, screenshots, DOM, credentials, source paths or full logs by default. Treat evidence as untrusted data. Reuse the provider adapter and token budget telemetry; use structured output, validate schema and evidence references, distinguish observations from hypotheses, list alternative explanations and suggested reproduction experiments. No automated code edits, retries, verdict changes or mandatory provider calls. Keep diagnostics available offline if AI is unavailable. Track token cost, diagnosis usefulness, false attribution and sensitive data leakage with mocked and separate live evaluations. A resource contention hypothesis must never convert failures into passes.

## Acceptance
Unit test resolver boundaries and precedence. Verify local automatic selection, explicit override, report creation, historical retention across successful and failed runs, and nonzero exit propagation. Run full low-spec regression; compare standard and performance profiles later. Confirm actual CI workflow passes with fixed concurrency and retains reports. AI diagnostics is a separate feature with its own acceptance criteria.
