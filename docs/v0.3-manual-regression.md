## Current sprint: actionability and negative assertions (approved, implementation outstanding)

Critical release blocker: a verification-only instruction such as "Verify that the Add button is clickable" currently may generate a click followed by a visibility assertion. This changes application state and does not prove clickability. A destructive click could have serious consequences. Visibility is not equivalent to clickability.

| ID | Scope | Priority | Status |
|---|---|---|---|
| ASSERT-01 | assert-clickable using Playwright trial click without dispatching click; standard actionability checks and unique locator resolution | Critical | Planned |
| ASSERT-02 | Prevent verification-only clickability checks from becoming state-changing actions; preserve explicitly requested clicks, surface unsupported/ambiguous semantics rather than silently substituting; cover initial generation and incremental editing | Critical | Planned |
| ASSERT-03 | assert-enabled | High | Planned |
| ASSERT-04 | assert-disabled | High | Planned |
| ASSERT-05 | assert-editable without modifying values | High | Planned |
| ASSERT-06 | assert-not-visible, covering hidden or absent intended element; ambiguous locator must not silently pass | High | Planned |

Implementation scope: domain/schema, runner, initial and incremental prompts, manual draft action editor, requirement mapping, saved definitions, results/diagnostics and applicable exports. Preserve human review and provenance. Existing scripts remain compatible. Trial click may scroll but must not dispatch a click; document that this is an actionability check, not proof that a click handler succeeds. Deterministic generation safeguards must not remove legitimate explicitly requested clicks. No hosted calls needed for automated tests.
