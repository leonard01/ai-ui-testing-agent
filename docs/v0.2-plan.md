# v0.2 implementation plan

**Status:** v0.2 development in increments. Run Tests redesign and working-draft persistence are on `main`. Incremental regeneration is in PR #38 awaiting CI and user testing; it is not yet released.

## Increment 2 — Working drafts and original instructions (merged)
- User-entered **Test name** sits in the Test Instructions panel.
- **Test Editor** initially displays website-suite/test selection and saved working drafts; the selection panel is replaced by proposed steps when editing begins.
- Approved test JSON may include original `sourceInstructions` and editable `workingInstructions`; legacy scripts show *Original instructions unavailable*.
- Partial review progress can be saved as a local working draft and resumed without entering information again; drafts stay out of runnable suites, exports and execution.
- Fully approved existing tests can be edited and saved in place, or **Save as New Test** to retain both scripts. New scripts require an explicitly entered different name.
- The same instructions can be edited and the complete test regenerated; targeted regeneration is added in the separate v0.2 increment below.
- No AI generation occurs when saving or resuming a draft.

## Phase 1 — Collaborative test editor and persistence
- Remove numbering from the creation/review panels and move required test naming into Test Instructions.
- Persist the original tester-supplied instructions separately from generated executable steps.
- Save incomplete/partially approved drafts independently of approved runnable scripts.
- Select existing website suite and test script for editing; preserve original instructions when reopening.
- Support **Save Changes** (replace existing with confirmation) and **Save as New Test** (new required name, original unchanged).
- Keep drafts out of all runnable suite lists and exported runnable scripts.

## Increment 3 — Incremental AI reinterpretation (PR #38, testing required)
- A **Reinterpret with AI** action is available on each step after the initial navigation.
- Tester chooses **Replace this step only** or **Replace this step and all following steps**, then writes fresh plain-English instructions.
- Groq receives the existing prefix (and unchanged suffix when relevant) as context and an **initial-page snapshot**, without executing preserved steps.
- Returned steps are validated as a bounded patch, previewed before explicit **Apply proposed steps**, and cannot claim human-confirmed provenance.
- The server preserves step IDs and approval state **outside** the changed range; changed steps get new IDs and require fresh review.
- Requirement links involving replaced steps are removed, with a warning to remap those links.
- **Save Working Draft** persists partially reviewed replacements. Approved tests and the original input instructions remain unchanged until the user explicitly saves an approved revision.
- This PR remains unmerged until user acceptance after CI.

## Phase 2 — Incremental AI generation
- Regenerate just one selected step, regenerate from a selected step, and insert proposed steps after a chosen step.
- Preserve accepted steps outside the requested edit range; require human confirmation for replacements.
- Save draft state and recover after restarting the review server.
- Later: optionally replay an approved prefix in an isolated browser and supply the resulting DOM to AI, with explicit protections against destructive replay.

## Phase 3 — Extended assertions and review
- Implement negative assertions and element state checks, including hidden, absent, enabled, disabled, checked and unchecked.
- Extend locator and target editing (e.g., semantic roles, container scope, DOM selection before execution).
- Add independent requirement-to-assertion coverage checks and clearly report unimplemented expectations.

## First increment — Run Tests selector redesign (#34)
- Suite and script dropdowns side-by-side; script disabled until user chooses a suite.
- On switching suite, clear script selection; restrict choices to that suite.
- Visually group Run selected test with a 5-second default step-timeout dropdown (5/10/15 seconds).
- Keep batch execution and use same selected timeout for both execution modes.
- Preserve browser keyboard access, labels, legacy scripts, export and edit functionality.

## Quality gates
- Typecheck, build, unit and browser tests pass.
- Run Tests acceptance: disabled script until suite chosen; suite change clears script; no automatic run; valid script enables actions; timeout changes do not execute.
- Original v0.1 functionality remains stable on main until each v0.2 PR passes review and CI.

## v0.2 — Application memory and prerequisite suggestions (implemented in PR #41; awaiting acceptance)
- Record **only** generic per-origin evidence from fully passed and human-approved test executions. The first supported signal is: a shopping workflow succeeded after login.
- Never store credentials, fill values, selectors, raw DOM snapshots or generated test instructions in the memory file; save the origin, a bounded count and last-observed timestamp.
- When the user asks to add items to basket/cart, look for this site's past evidence and **suggest** that login may be required. Show the suggestion and include it in the AI context as an **unverified historical clue**, not a mandatory requirement.
- Tester may disable **Use successful-test knowledge from this website** before generating; it never bypasses step approval.
- A test passing with an invalid-login error or a login-only scenario must **not** be interpreted as proof that shopping requires authentication.
- Existing run/test storage is not retroactively mined; observations start when successful tests execute on the updated branch.
- Not covered in this first increment: generic workflow retrieval, selector reuse, authenticated browser-state discovery, automatically supplying credentials, or storing entire successful tests.
